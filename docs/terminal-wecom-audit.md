# 终端与企业微信桥接检查记录

检查日期：2026-11-18。结论适用于本次工作区修改，未发布。

## 检查结论与修复

| 范围 | 原有问题 | 本次处理 |
| --- | --- | --- |
| 终端布局 | 尺寸未变化时，布局通知仍重复调用 fit，输入稳定性回归检查失败 | 对比目标行列数，跳过重复 fit；保留视口同步、刷新和 DPI 恢复 |
| CLI 原生问题 | 只有 Claude 创建原生交互观察器，CodeBuddy / Codex 的菜单和文字问题未接入该通道 | 三种 CLI 共用识别、当前焦点校验、逐键导航及确认机制；问题标题标识实际 CLI |
| 问题重试 | `/retry` 仅允许 Claude | 支持三种已授权 CLI 会话 |
| CodeBuddy 本机任务 | 只有 Stop，没有 UserPromptSubmit，本机提交时可能没有 pending 任务，最终结果被忽略 | 增加提交钩子和等待输入通知钩子 |
| Codex 本机任务 | notify 只有完成通知，本机提交后可能没有 pending 任务 | 记录本机提交，允许对应完成通知进入结果处理；Ctrl+C、停止和完成撤销记录 |
| 企业微信文字回复 | `/回答` 对前导空白、制表符处理不一致；纯文字问题的数字回答被当作选项编号；普通自定义回答缺少统一长度与控制字符检查 | 统一解析和校验，保留有效多行内容，无选项时接受数字文字 |
| 提交竞态 | 粘贴与回车之间只检查会话对象，未再次确认前台 CLI、本机接管、停止或终端替换 | 回车前再次检查实际进程、终端身份、输入版本和任务身份；条件变化时停止提交 |

企业微信入站仍按绑定账号、消息 ID 去重和会话归属处理。引用消息选择原会话，卡片回答校验问题标识和账号；过期、本机接管或尺寸变化后的旧卡片不能继续向终端输入。最终回复继续使用 CLI 的结构化完成通知，终端重绘和输入回显不作为最终结果。

## 已执行验证

- 真实 Electron 终端：输入稳定性、底部和右侧停靠、拖动改变尺寸、缩放和 DPI 恢复、隐藏后恢复、滚动历史、ANSI 颜色、应用鼠标协议、中文候选词 Enter / Escape。
- 输入稳定性最终结果：两种停靠下几何位移均为 0、输入期间 resize 事件均为 0，重复布局的 fit 次数为 0，标签节点保持不变，实际拖动仍正确同步 PTY 尺寸。
- 滚动最终结果：保留约 5000 行历史，连续 24 次向上滚轮没有重复记录或修改历史；普通、256 色、真彩色均正确；备用屏幕与鼠标协议保持应用行为。
- 三种 CLI 的模拟完整回路：终端屏幕 → 问题详情和卡片 → 企业微信编号 / 卡片 / 文字回复 → PTY 按键 → 界面变化确认 → 结构化最终结果。覆盖重绘、旧卡片、尺寸变化、过期重试、卡片发送失败后的文字回退。
- 新增竞态测试：本机接管、CLI 退出、PTY 替换、停止期间不再发送回车；本机 Codex 最终结果只发送一次，停止后的结果被抑制；CodeBuddy 提交钩子配置正确。
- 原有相关测试通过：terminal-output、terminal-process、terminal-command、cli-session、cli-native-interaction、cli-native-delivery、cli-sequential-questions、cli-result-channel、cli-trust、cli-interactions、cli-wecom-approval、wecom-service、wecom-question-modes、cli-progress、wecom-files、history-bridge。
- `git diff --check` 通过。输入稳定性测试同时更新了已移除页面元素的旧定位。

## 验证边界

本次没有向真实企业微信账号发送测试消息，也没有调用三种 CLI 的真实模型完成选择题。双向问题回路使用真实应用模块、headless xterm 和模拟企业微信客户端 / CLI 屏幕；结果钩子测试实际执行辅助进程。终端界面检查使用真实 Electron 和 PowerShell。

原生问题识别仍取决于 CLI 的实际界面格式：当前支持带明确焦点、编号 / 复选框及操作提示的菜单、文字输入和已实现的历史选择布局。CLI 升级、更换语言、未覆盖的特殊界面可能无法识别；`/retry` 不能识别时应在本机处理。不能据本次模拟回路推断所有 CLI 版本的真实问题均已验证。

网络断开、企业微信接口拒绝、CLI 没有发出完成钩子不属于本次成功路径的交付保证。现有发送通道仍有文本长度上限，发送失败没有持久化补发队列；因此本次结论为本地逻辑与已覆盖路径通过，不能保证离线恢复后的最终消息必达，也不能保证超长结果完整发送。

## 文字回答与多选补查

`/回答` 通常不是必需的。当前聚焦会话只有一道待回答问题时可以直接回答；需要明确指定问题、跨会话回答或原样输入 `/stop` 等控制命令时使用 `/回答 12位问题编号 内容`。固定选项题应先选择选项或“其他”，终端进入文字输入步骤后再回复自由文字。错误格式的 `/回答` 现在只返回用法，不会转发成新的 CLI 消息。

本轮另行修复多选的快速点击丢失、回调重复导致反向取消、编号选项中 `☒` 状态漏识别、其他问题的复选框干扰当前单选、焦点位于 Other 时误判文字输入，以及提交前未复核整组选中状态的问题。卡片操作串行处理并按回调标识去重；翻页保留勾选；文字编号提交完整选择集并替换卡片勾选；当前规则要求至少一项。终端短暂清屏后重绘同一问题时，增加消失稳定期，避免旧卡片被过早作废。

新增 `wecom-question-replies` 和 `wecom-multiselect-roundtrip` 测试，覆盖直接多行回答、指定其他会话、引用回复、多个问题消歧、控制命令作为回答、空多选拒绝，以及三种 CLI 各自的卡片 / 文字多选完整回路、初始勾选、快速点击、重复回调、跨页、取消勾选和提交前状态变化。
