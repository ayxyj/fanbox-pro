# 企业微信会话、CLI 与文件发送

## 会话命令速查

| 命令 | 用途 |
| --- | --- |
| `/projects [页码]` | 列出工作目录的直接子目录，每页 20 个 |
| `/new [项目名或完整路径]` | 新建并聚焦终端；目录必须已存在，省略时使用工作目录 |
| `/list` | 列出当前账号仍打开的桥接会话、编号、项目与状态 |
| `/list 2` 或 `/sel 2` | 切到编号 2；编号以列表为准 |
| `/sel 会话id` | 按完整会话 ID 切换 |
| `/content` | 查看聚焦终端最近内容；快照不代表完成 |
| `/claude`、`/codex`、`/codebuddy` | 在真实终端中进入相应 CLI |
| `/aiquit` | 请求退出 CLI，确认回到 Shell 后恢复内置 AI 模式 |
| `/permiss` | 切换一次 Claude 权限模式，并读取实际状态 |
| `/retry` | 重新发送当前 Claude 终端仍在等待处理的问题；旧卡片同时失效 |
| `/状态` | 查看当前任务是否仍在运行或等待确认 |
| `/stop` | 停止当前聚焦会话的任务 |
| `/set_name 英文名 中文名 [昵称]` | 首次设置身份，修改时加 `--force` |
| `/help` | 内置 AI 模式下查看帮助 |
| `/bridge` | CLI 模式下查看桥接帮助，避免与 CLI 自己的 `/help` 冲突 |

`/new` 是创建会话，不是创建文件夹。例如工作目录为 `D:\code`，`/new demo` 对应 `D:\code\demo`。

## 多会话如何续聊

直接发送文字会续聊当前聚焦会话。引用某条桥接推送再回复，可定位到那条推送所属会话。原任务的审批和结果仍属于原会话，切换焦点不会把它迁移到其他终端。

`/list` 显示当前软件进程中仍打开的桥接终端，不是全部历史清单。重启软件后不会自动恢复全部旧终端或重跑任务；旧聊天历史在对应本机历史中查看。

## 进入 CLI 后的消息去向

先发送 `/new demo`，再发送 `/claude`。CLI 启动后，普通消息原样送入 CLI，不再由内置 AI 先分析。CLI 使用自身的模型、登录与权限配置。

通过企微 `/claude` 启动时默认追加 `--permission-mode auto`。软件内 Claude 快捷入口及历史会话恢复也使用 auto 模式；实际可用性取决于 Claude 的模型及组织策略。已运行的 CLI 需退出后重新启动才应用新参数。

若提示无法确认前台进程，消息不会被当作系统命令盲目发送。查看本机终端是否已进入 CLI，处理启动确认后再试。想回到内置 AI 时发送 `/aiquit`，等待确认退出；它不是简单切换一个界面标签。

## 信任、批准与追问

Claude / CodeBuddy 初次进入项目可能询问是否信任目录。企微会收到对应选择；CodeBuddy 可区分当前目录、父目录和子目录范围。按实际需要选择，不要把父目录信任当成当前项目的同义项。

运行过程中出现权限卡片时，核对所属会话后点击批准或拒绝。卡片只针对当前操作，旧卡片不能批准新任务。普通 AI 审批通常 5 分钟有效；CLI 的部分权限与追问窗口为 4 分钟，以提示为准。

Claude 的选择题可按卡片单选、多选、提交或自定义文本回答。多选需要提交；文本回答发到当前聚焦的待回答会话。跨会话可按提示使用 `/回答 问题编号 内容`。

文件写入 / 修改授权只展示路径、操作类型、内容大小或修改数量，不再推送整份源码 JSON；其他操作仍保留用于判断的必要内容。

> 如显示“已批准；卡片更新失败，本次决定已记录”，不要反复点击。批准已记录，但企微卡片外观未更新；查看终端或后续结果确认。

## 进度和最终结果

采用固定的“少量进度通知 + 关键节点交互 + 最终结果”。短任务一般不发送普通进度；长任务限频更新，等待审批或限流重试时暂停普通进度。终端动画、输入回显和界面重绘不会逐行转发。

最终结果依赖 CLI 的完成通知，不把暂时没输出当作成功。需要临时查看原始终端时，用 `/content`。

同一个桥接 Claude 会话中，在本机终端提交的任务也会跟踪并转发最终结果；终端的正常显示和输入保持不变。

## 发送文档、图片和截图

可以发送：

```text
生成一份项目说明，保存为 Markdown，再把文件发送到当前企业微信会话。
```

```text
调试完成后截取网页，保存截图，再把截图文件发给我。
```

截图由 Agent 使用自己的工具完成；FanBox 负责将已经生成的本地文件上传并发送到当前账号。图片作为可下载文件发送。

单文件最大 50 MB，不支持目录、空文件或仍在变化的文件。远端 SSH 文件先下载到本机。工具不接受任意收件人参数，只发给当前会话绑定账号。

当前附件能力是**电脑向企微发送文件**，不表示支持把企微用户上传的所有附件自动下载交给 Agent。发送状态不确定时先检查企微是否已收到，不要立即重复发送。

## Claude 原生交互同步

新开启的 Claude CLI 保留终端原生的授权、问题和选择界面。绑定的企微会话同步可识别的当前菜单，可点击按钮或回复编号；多选可回复 `1,3`。进入自由输入步骤后可直接回复内容。

同一终端一次只推送当前正在显示、具有焦点的一道问题。多道问题依照终端顺序逐题发送：回答问题 1 并确认终端已进入下一题后，才推送问题 2；后续问题不会提前发送。同一题的位置变化或界面重绘不会另建卡片。不同终端会话各自独立。

例如 Claude 连续询问“语言 → 数据库 → 部署方式”：先只回答语言，终端进入数据库问题后企微才发送第二题，再依次回答部署方式。每一道题分别有完整的 4 分钟回答时间，前一题耗时不会扣除后一题的时间。通常每题包含一条详情消息和一张选项卡片；这是同一道问题的说明与操作入口。

- 在终端移动选择、输入、提交或退出后，旧企微卡片会失效；界面稳定后同步当前选项。终端的焦点切换和状态回报不会取消问题。
- 在企微提交前再次校验 CLI 进程、终端身份和当前菜单；旧卡片不会操作后续问题。一端操作后，另一端不能重复提交。
- 方向键、空格、文字与回车逐个回传；实际焦点和勾选状态更新后才提交。终端离开原问题后才提示“选择已生效”。若提示“尚未确认生效”，不会自动重复提交或推送同一问题，可用 `/retry` 获取新卡片。
- `/resume` 原样交给 Claude，企微显示当前可见的历史会话和说明。卡片中的“下一组选项”只翻企微卡片；“终端下一屏 / 上一屏”移动 CLI 列表。回复 `搜索 关键词` 筛选会话，看到更新后的选项再选择。
- 恢复成功以 Claude 的会话恢复事件为准；终端列表或问题界面发生变化不等同于历史会话已经恢复。企微问题四分钟后过期，本地菜单仍可操作；发送 `/retry` 获取当前问题的新卡片。
- 选项卡片发送失败但文字详情已送达时，可以直接按提示回复编号或使用 `/回答 问题编号 内容`。自由输入支持以 `/` 开头的路径；桥接控制命令仍保留用途，需原样回答控制命令时使用 `/回答`。
- 菜单识别依据当前终端画面，不读取旧滚动历史。CLI 界面版本变化或菜单无法可靠识别时，请在终端操作。

升级后需要退出原来的 Claude CLI，再通过 `/claude` 启动，旧进程仍使用启动时生成的 Hook 设置。此功能仅针对通过 FanBox 桥接启动且已绑定企微的 Claude 会话。
